Eight tools, one job each

No framework, no plugins, no configuration language. One binary per problem, and every claim below has a command behind it.

hedge

Transparent CONNECT tunnel that replays a TLS handshake when the server drops before the first byte. The client never notices.

https_proxy=…:8899 curl …

ghostfs

FUSE filesystem where the network is a directory. Written straight on the /dev/fuse protocol, no libfuse.

cat /net/<host>/<path>/get

spool

Durable queue: a job is claimed by an atomic rename, so it runs exactly once even if the worker is killed mid-flight.

spool add --key K -- cmd

shelf

Deduplicates a directory with hard links. No hashes — files are compared byte by byte, so a match is a proof, not a probability.

shelf --dir ~/Downloads

autosort

Deterministic directory sorter. Dry-run first, explicit --dir required, a 200-file guard, and a journal for every move.

autosort watch --dir … --apply

netwatch

Probes that make degradation visible — success rate, latency, and the windows when a line starts dropping handshakes.

netwatch probe --rounds 5

jitter

Scheduler jitter: p50, p99, p99.9 and max wake-up lateness. Smoothness is a tail property, not an average.

jitter --samples 2000

rtprio

Runs a process with SCHED_FIFO and realtime I/O priority, then reads the actual policy back from /proc.

rtprio -- firefox

Limits, stated plainly

A tool that hides its boundary is a tool you cannot trust.

  • hedge rescues a connection only before the first response byte. A drop mid-download is a resume, not a replay. It does not terminate TLS.
  • ghostfs cannot list a web server's paths — directories inside a host are deliberately empty instead of invented.
  • shelf links only within one filesystem and only on exact equality; a hard link shares the inode, so editing one copy edits both.
  • autosort once sorted the real ~/Downloads; 503 files were restored from the journal, and the guard exists because of it.
  • rtprio without CAP_SYS_NICE says Operation not permitted instead of pretending.
  • eBPF items are blocked here: unprivileged_bpf_disabled=2, no bpftrace, no kernel headers.
